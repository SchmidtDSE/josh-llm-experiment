Implement this using the Josh DSL. Author `.josh` model files and any `.jshd` preprocessing artefacts the model needs; do not implement the model in Python. Your implementation can use python for discovery and initial analyses, but it should not use python for any post-processing — the resulting csv must be generated by the josh runtime, not through any post-hoc handling of the output csv from josh. Doing so will result in task failure.

`./run.sh` must do the whole workload end-to-end: build the `.jshd` preprocessing artefact(s) by invoking `josh preprocess …` against the netCDF inputs, then invoke `josh run --replicates 100 …` to run the 100-year × 100-replicate simulation, and emit the output CSV(s) from Josh's native export. Do not split preprocessing into a separate manual step the user has to run first — the scorer invokes `./run.sh` exactly once.

Canonical Josh output for multi-replicate runs is one CSV per replicate, via the `{replicate}` template variable in your `exportFiles` URL:

```josh
exportFiles.patch = "file:///sandbox/output/results_{replicate}.csv"
```

That writes `output/results_0.csv` … `output/results_99.csv`. The scorer globs them and uses the integer in the filename as the replicate index — no `replicate` column is needed inside each file.

You must read the josh documentation at https://raw.githubusercontent.com/SchmidtDSE/josh/refs/heads/dev/llms-full.txt.
