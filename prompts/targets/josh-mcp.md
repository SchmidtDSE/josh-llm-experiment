Implement this using the Josh DSL. Author `.josh` model files (plus any `.jshc`
config your model needs); do not implement the simulation in Python. The result
CSV must be generated by the Josh runtime — post-hoc handling of Josh's output
(recomputing values, restructuring rows, etc.) is a task failure.

### Your environment is constrained — Josh only, no shell

You have **no `bash`** and cannot run shell commands or scripts. You drive Josh
**only through the MCP tools** the `josh` server exposes (you will see them in your
tool list, prefixed `josh_`):

- `josh_validate_simulation` — parse/validate a `.josh` script.
- `josh_preprocess_data` — build a `.jshd` from a netCDF (args: `script`,
  `simulation`, `dataFile`, `variable`, `unitsStr`, `outputFile`).
- `josh_run_simulation` — run a simulation (args: `script`, `simulation`,
  `replicates`, optional `data` map of `name.jshd → path`, `seed`).
- `josh_discover_config` — inspect a script's config/externals.

Pass **absolute `/sandbox/...` paths** to every tool. `webfetch` is available for
reading the Josh docs (linked below); `read`/`write`/`edit`/`glob`/`grep` work on
your `/sandbox` workspace.

### Do NOT write or run `run.sh`

There is no `./run.sh` for you to author or execute — the scorer supplies its own
canonical run. **Ignore any instruction elsewhere in this prompt to "invoke
`./run.sh` to self-test"**; that path does not exist for you. Self-test with
`josh_run_simulation` instead.

### Required structure (the scorer runs your model by this convention)

Your deliverable is Josh source + the `.jshd` you build via `josh_preprocess_data`.
The scorer will run exactly:

```
josh preprocess --x-coord lon --y-coord lat --time-dim calendar_year \
  simulation.josh Main data/maxtemp_synthetic.nc tasmax K temperature.jshd
josh preprocess --x-coord lon --y-coord lat --time-dim calendar_year \
  simulation.josh Main data/precip_synthetic.nc pr "kg m-2 s-1" precipitation.jshd
josh run simulation.josh Main --replicates 100 \
  --data temperature=temperature.jshd --data precipitation=precipitation.jshd
```
(The MCP `preprocess_data` tool auto-detects the netCDF coordinate dims, so you
don't pass `--x-coord/--y-coord/--time-dim` in your self-test — the harness CLI
needs them explicit, shown here only so you know the data binding the scorer uses.)

So your model **must**:

- live in an entry file `/sandbox/simulation.josh` with a simulation named `Main`;
- declare exactly `external temperature` and `external precipitation` (these bind
  by filename stem to `temperature.jshd` / `precipitation.jshd`);
- read `temperature` as Kelvin and `precipitation` as the raw flux `kg m-2 s-1`,
  and do the `× 31_536_000` → mm/year conversion **inside the model** (see the
  spec sheet below);
- write output via `exportFiles.patch = "file:///sandbox/output/results_{replicate}.csv"`.

### Self-test loop (mirror the scorer's commands)

Build and validate your model with the MCP tools, using the **same** arguments the
scorer will, so a green self-test predicts a green scoring run:

1. `josh_validate_simulation(script="/sandbox/simulation.josh")`
2. `josh_preprocess_data(script="/sandbox/simulation.josh", simulation="Main", dataFile="/sandbox/data/maxtemp_synthetic.nc", variable="tasmax", unitsStr="K", outputFile="/sandbox/temperature.jshd")`
3. `josh_preprocess_data(script="/sandbox/simulation.josh", simulation="Main", dataFile="/sandbox/data/precip_synthetic.nc", variable="pr", unitsStr="kg m-2 s-1", outputFile="/sandbox/precipitation.jshd")`
4. `josh_run_simulation(script="/sandbox/simulation.josh", simulation="Main", replicates=2, data={"temperature.jshd": "/sandbox/temperature.jshd", "precipitation.jshd": "/sandbox/precipitation.jshd"})`

Iterate (read the tool errors, fix the `.josh`, re-run) until a 2-replicate run
succeeds and writes the expected CSVs. The scorer reruns at 100 replicates.
